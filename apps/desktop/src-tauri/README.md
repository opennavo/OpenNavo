# Desktop Rust core

Rust commands and events are the IPC source of truth. `src/ipc/bindings.ts` is generated by tauri-specta; do not edit it manually. Regenerate with `pnpm --filter @opennavo/desktop gen`. Development and test writes must use `OPENNAVO_BREW_PATH` pointing to `tests/fake-brew/brew`; never start automatic scheduling against the development machine's Homebrew.

```sh
cargo fmt --manifest-path apps/desktop/src-tauri/Cargo.toml --check
cargo clippy --manifest-path apps/desktop/src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml
pnpm --filter @opennavo/desktop gen
```

## Local self-update verification

`tauri.conf.json` configures the update public key and stable manifest URL. `tauri.beta.conf.json` overrides only the beta manifest URL, merged through Tauri CLI `--config`. Updater access is limited to the main window, without automatic network checks. Settings → About (`src/components/settings/AppUpdater.vue`) uses the matching `@tauri-apps/plugin-updater` version for manual checking, downloading, installation, and restart.

The pinned Tauri version cannot prevent `request_restart` with `prevent_exit`. Rust preserves the process plugin's commands and permissions, adding queue checks to its existing restart entry point. Running/queued tasks reject restart with `active_tasks`; an idle restart atomically blocks new tasks, cleans notifications, then restarts. Exit still requires quit confirmation. The frontend disables restart while tasks are active and handles rejection; no additional IPC was introduced.

```sh
cargo run --manifest-path apps/desktop/src-tauri/Cargo.toml --example updater_verify
```

This demonstration calls the real updater plugin against manifests, signatures, and downloads served on a random local port, replacing a temporary synthetic app from 0.0.1 to 0.0.2. MockRuntime starts no GUI; the synthetic app is not executable and never replaces an installed app. Public fixture locations, regeneration, and invalid-signature regressions are documented in `tests/fixtures/updater/README.md`. Tests require neither private keys nor external network access.

Native bundle verification reuses the built frontend `dist`, copying artifacts and writing temporary configuration only inside its own target directory:

```sh
python3 apps/desktop/src-tauri/tests/verify_bundle.py --frontend-dist apps/desktop/dist
```

The script uses a development key in an ignored directory. If missing, first run the public fixture generator. It clears inherited production signing variables, disables Apple signing/notarization, sets rehearsal version 0.0.2 through temporary configuration, and creates host-architecture App/DMG artifacts. Because `--no-sign` also skips updater signing, the script signs the updater archive separately, then downloads/verifies it with the real plugin and replaces a temporary 0.0.1 app. It neither opens the app nor writes user installation directories. Results are in `target/dev_updater/bundle_verify/report.json`. Cross-architecture builds, CI/uploads, and production update demonstrations belong to `release-desktop.yml`.

Production releases use the update private key from CI secrets, paired with `plugins.updater.pubkey` in `tauri.conf.json`. `release-desktop.yml` overrides only the version through temporary configuration, additionally merging `tauri.beta.conf.json` for beta; it does not replace the public key or stable endpoint. For independent distribution, set your own identifier, update key pair, CSP, updater endpoints, and CDN domains in `src/core.rs`. Private keys come only from CI secrets, never local development keys. Tauri CLI signatures record the app version; the plugin rejects archives whose signed version differs from the manifest. Downgrades are disabled by default.

The architecture requires Rust ≥1.96. Release build dependencies use `strip=false` to avoid macOS LINKEDIT alignment failures in stripped procedural macros. These dependencies are not bundled; the final executable remains stripped according to the release profile. See the [Rust compiler issue](https://github.com/rust-lang/rust/issues/157750) and [Cargo build overrides](https://doc.rust-lang.org/cargo/reference/profiles.html#build-dependencies).
